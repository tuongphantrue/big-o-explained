The six you'll actually meet

Complexity classes, plainly explained

Ordered from calmest to most alarming. The color of each card tracks its position on that scale — the same cool-to-warm gradient as the chart above.

O(1)

Constant time

Takes the same number of steps no matter how big the input is. Adding a thousand more items costs nothing extra.

arr[5] // array index map.get(key) // hash lookup stack.push(x) // push/pop

Common in: array indexing, hash map get/set, stack push/pop, checking if a number is even.

O(log n)

Logarithmic time

Each step throws away a chunk of the remaining input, usually half. Doubling the input only adds one extra step.

while (low <= high) { mid = (low+high) / 2 // narrow to one half }

Common in: binary search, balanced binary search trees, finding an element's position in a sorted array.

O(n)

Linear time

Steps grow one-to-one with input size. Touch every item once and you're here — the most common complexity of all.

for item in list: total += item

Common in: linear search, printing an array, copying a list, finding the max of an unsorted collection.

O(n log n)

Linearithmic time

One linear pass, repeated across log n layers of splitting. The best you can generally do for comparison-based sorting.

function mergeSort(arr) { split in half // log n layers sort each half // recursive merge (n work) // per layer }

Common in: merge sort, quicksort (average case), heap sort, most "sort it then work with it" algorithms.

O(n²)

Quadratic time

A loop inside a loop, each one running across the full input. Fine for small n, punishing once n reaches the thousands.

for i in list: for j in list: compare(i, j)

Common in: bubble sort, insertion sort, checking every pair in a collection, naive duplicate detection.

O(2ⁿ)

Exponential time

Every additional item doubles the work. Practical only for small n — the kind of growth that turns "instant" into "overnight."

function fib(n) { if (n <= 1) return n return fib(n-1) + fib(n-2) }

Common in: naive recursive Fibonacci, generating all subsets of a set, brute-force solutions to NP-hard problems.
